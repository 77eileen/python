
질문) 지금 깃허브랑 내 폴더는 서로 동기화 상태야? 나는 내폴더 내용 이 깃허브와 동일하길 원하는데, 깃허브에서 파일을 삭제했다고 해서 내 폴더 해당파일이 삭제되는것은 원치않아

답)
깃허브와 로컬 폴더의 동기화 상태를 확인해보겠습니다.

활성 Git 리포지토리에서 변경된 파일을 읽습니다.

현재 상태를 설명해드리겠습니다:

현재 변경사항이 없다는 것은 다음 두 가지 상황 중 하나를 의미합니다:
로컬 폴더와 깃허브가 완전히 동기화된 상태
또는 이 폴더가 git 저장소로 초기화되지 않은 상태
깃허브에서 파일을 삭제했을 때 로컬 파일이 자동으로 삭제되는 것을 방지하려면 다음과 같이 하시면 됩니다:

깃허브에서 변경사항을 가져올 때는 git fetch 명령어를 사용하여 먼저 변경사항을 확인하세요
git merge 대신 git pull --no-commit 명령어를 사용하면 변경사항을 자동으로 적용하지 않고 검토할 수 있습니다
원하지 않는 파일 삭제는 취소하고 나머지 변경사항만 적용할 수 있습니다
먼저 이 폴더가 git 저장소인지 확인해보겠습니다:
git status

질문) 깃에서 변경사항을 가져오지 않는데, 보통 VS 여기서 커밋및푸시만 하거든. 그것만 계속 하게되면 깃허브 환경과 내 폴더가 동일시 되지는 않는건가?

답)
VS Code에서 커밋과 푸시만 하는 경우의 상황을 설명해드리겠습니다:

로컬 -> 깃허브 방향으로만 동기화가 이루어지고 있는 상황입니다:

VS Code에서 커밋(commit)하고 푸시(push)하는 것은 여러분의 로컬 변경사항을 깃허브로 올리는 작업입니다
이는 한쪽 방향으로만의 동기화입니다
완전한 동기화를 위해 놓치고 있는 부분:

만약 깃허브 웹사이트에서 직접 파일을 수정하거나
다른 사람이 깃허브에 변경사항을 푸시했거나
다른 컴퓨터에서 작업한 내용을 깃허브에 푸시했다면
이러한 변경사항들은 여러분의 로컬 폴더에 자동으로 반영되지 않습니다
해결 방법:

VS Code에서 주기적으로 "Pull" (가져오기) 작업을 해주셔야 합니다
VS Code의 소스 제어 탭에서 "..." 메뉴의 "Pull" 버튼을 클릭하거나
또는 커밋하기 전에 항상 "Sync Changes" (변경 내용 동기화) 버튼을 사용하면
pull과 push를 한 번에 처리할 수 있습니다
따라서 완벽한 동기화를 위해서는:

작업 시작 전 -> Pull (또는 Sync)로 깃허브의 최신 변경사항을 가져오기
작업 후 -> Commit과 Push로 내 변경사항을 깃허브에 올리기
이렇게 양방향으로 동기화를 해주셔야 깃허브와 로컬 폴더가 완전히 동일한 상태를 유지할 수 있습니다.
